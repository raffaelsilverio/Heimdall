# Heimdall Browser Worker

Python worker for the loopback browser automation boundary. The Go core owns
policy, programs, scope and test accounts; this worker only creates isolated
browser sessions for identities the core has already authorized.

## Status

The worker protocol, loopback HTTP server and session isolation are implemented.
The Playwright/Chromium driver is **not integrated yet**: the default driver is
unavailable, `/healthz` reports `available: false`, and every session request
fails closed with HTTP 503. The next increment adds the reviewed driver and the
Browser Manager lifecycle.

## Run

```sh
cd browser
export HEIMDALL_BROWSER_TOKEN="$(openssl rand -hex 32)"   # 32-256 printable ASCII
python3 -m heimdall_browser --port 8090 --max-sessions 8
```

The token is read only from the environment and is never printed or persisted.
The worker refuses any bind address other than `127.0.0.1`.

## Protocol

All routes require `Authorization: Bearer <token>`. Bodies are capped at 16 KiB,
must be a single JSON object with unique keys, and unknown fields are rejected.
Responses carry `Cache-Control: no-store` and never include cookies, tokens,
storage state, or credentials.

| Method | Path | Purpose |
|---|---|---|
| `GET` | `/healthz` | Protocol version and driver availability |
| `POST` | `/v1/sessions` | Open one session for a program/test-account pair |
| `GET` | `/v1/sessions/{id}` | Read session metadata |
| `DELETE` | `/v1/sessions/{id}` | Close the session and its browser context |

`POST /v1/sessions` accepts exactly:

```json
{
  "program_id": "program-id",
  "test_account_id": "account-id",
  "scope_hash": "64 lowercase hex characters",
  "policy_revision": 3
}
```

Session ids are generated by the worker. One live session exists per
(program, test account) pair; the same account id in another program, or another
account in the same program, gets a separate session. The concurrent session cap
defaults to 8 and is bounded to 32.

## Security invariants

- Loopback-only listener, bearer token on every request, constant-time compare.
- No redirects, query strings, duplicate JSON keys, chunked bodies, or oversized
  bodies. Error messages never echo request bodies.
- Session metadata is the only data returned to the core. Cookies and tokens
  stay inside the driver's browser context.
- Access logs contain only the matched route name and status, never headers,
  paths with queries, or bodies.
- The core must validate program policy, scope, approval and the test account
  before calling this worker; the worker never grants authorization.

## Tests

```sh
python3 -m unittest discover -s tests -t .   # from browser/
```

Tests use only the standard library and never launch a browser.
